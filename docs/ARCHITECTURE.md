# Архитектура

Документ описывает, как устроены сценарии, какие контракты у разметки сайта и
что осталось техническим долгом. Рассчитан на того, кто будет поддерживать
проект после изменения разметки online-mahalla.uz.

## 1. Общая схема

```
Excel-таблица ──► ExcelReader ──► ExcelRow (строка = один человек)
                                     │
var/state/*.json ◄── Progress / MembersState / StreetsState / CadasterRegistry
                                     │
                                     ▼
                            FamilyAutomation / HouseholdAutomation
                                     │
                              BrowserAutomator (Selenium + Edge)
                                     │
                      отчёты Excel, логи, скриншоты в var/
```

Оба сценария — самостоятельные модули с одинаковым слоем работы с браузером:
`BrowserAutomator` (запуск Edge, JS-хелперы, ожидания, тосты, HTTP-ошибки) и
набор утилит (`norm_text`, `digits_only`, `birth_from_pinfl`,
`generate_uzbek_phone`, `classify_error`).

## 2. Жизненный цикл прогона (family)

1. `load_rows()` — читает Excel от `START_ROW`, ключ строки — колонка `ID`.
2. `run()` — открывает страницу района, ждёт авторизацию, обходит улицы.
3. `read_streets_from_page()` / `street_units()` — список улиц; уже пройденные
   берутся из `family_streets_state.json`.
4. `read_street_links()` — ссылки `/forms/survey_homes/{id}`; кадастр и home_id
   вытаскиваются из текста строки и URL.
5. `process_cadaster()`:
   * кадастр уже готов (30 «Бошқа») → пропуск без открытия формы;
   * иначе открывается форма, вкладка «Хонадон аъзолари», читается счётчик;
   * цикл `while count < target`: `next_row()` → `add_member(row)`.
6. `_finish_cadaster()` — счётчик и статус пишутся в состояние и отчёт.

`next_row()` выдаёт только те строки, которых нет в `used_rows`
(`family_members_state.json`), поэтому один человек не попадает в два хонадона и
повторный запуск не тратит уже израсходованные строки.

## 3. Контракты разметки

| Что | Как ищем | Особенность |
|---|---|---|
| Вкладка членов семьи | текст «Хонадон аъзолари» + fallback-и | открывается `JS_OPEN_TAB` |
| Строки таблицы | `div.tab-pane.active` → `table.platon-table tbody tr` | счётчик «Бошқа» — точное совпадение нормализованного текста ячейки |
| Кнопка добавления | «Қўшиш», fallback — `button.save-btn` | модалку открывает именно «Қўшиш» |
| Модалка | видимый `div.vm--modal` / `div.modal` с `fieldset[data-name]` | атрибута `form-name` нет |
| Поля | `fieldset[data-name="relationship"/document_type/doc_serial/doc_number/birth_date/pinfl/full_name/phone/study_level_id` | `full_name` заполняет сайт после поиска |
| Поиск по ЖШШИР | кнопка `pa-inline-btn` с `title="ЖШШИР бўйича қидириш"` | в модалке две кнопки «Қидириш» |
| Списки | нативный `select` + Select2 | в `<option>` **пустые подписи** |
| Тост ответа | `.b-toast` (`.toast-header strong`, `.toast-body`) | класс `b-toast-danger/success/warning` + текст заголовка |

### Пустые подписи в списках

`_learn_options()` открывает Select2, читает отрисованные тексты и сопоставляет
их по порядку со значениями нативных опций — получается карта
`{подпись: значение}`, которая кэшируется в `option_maps`. Дальше значение
выставляется напрямую в `select` (`JS_SET_FIELDSET_SELECT_VALUE`) и
проверяется через `JS_FIELDSET_SELECT_STATE`.

Почему не кликами: после смены одного списка Vue перерисовывает модалку, ссылки
Selenium становятся stale. Поэтому каждое обращение к полю идёт через
`_fresh_fieldset()` (повторный поиск модалки и fieldset).

### Закрытие выпадающего списка

ESC в BootstrapVue закрывает **модалку целиком**, поэтому `_close_dropdown()`
не нажимает клавиши — только снимает класс `select2-container--open`.

## 4. Обработка отказов сайта

Классификация берётся из тостов и HTTP-перехвата:

| Ответ сайта | Реакция |
|---|---|
| «Хабар: Маълумотлар сақланди» | успех, счётчик перечитывается |
| «Диққат: Майдонлар тўғри тўлдирилганлигини текширинг» | ошибка строки → строка помечается использованной |
| «Хатолик: Request failed with status code 400» + текст `қайта киритиб бўлмайди` | человек уже есть в другом хонадоне → строка использована |
| «Хатолик / Ma‘lumot topilmadi … Ҳужжат тури тўғри танланганини текширинг» | данные не найдены → строка использована |
| «So‘rovlar ko‘payib ketdi. N soniya kuting» | пауза N секунд, строка остаётся в очереди |
| окно браузера закрылось | браузер перезапускается, кадастр открывается заново |

Коды-маркеры: `ROW_SKIP_PREFIX`, `RATE_LIMIT_PREFIX`. Порог подряд неудачных
строк на кадастр — `MEMBER_FAIL_LIMIT`.

## 5. Состояние и повторный запуск

| Файл | Содержимое |
|---|---|
| `family_members_state.json` | `cadasters[key].boshqa` — сколько «Бошқа» уже есть; `used_rows` — израсходованные строки таблицы |
| `family_progress.json` | какие ключи строк обработаны и с каким итогом |
| `family_streets_state.json` | пройденные улицы |
| `family_streets_found.txt` | найденные на улицах кадастры |
| `family_cadasters.txt` | реестр заведённых кадастров |
| `family_ignored.txt` | строки, которые повторять не нужно |

Запись состояния идёт сразу после изменения (`_flush`), поэтому прерывание
прогона не теряет прогресс.

   стоит включить `--no-trace-js` или добавить ротацию.

   сценариями).
